# Sunset Rush 3.0 — المرحلة الأولى: سلاسة العرض والكاميرا

تاريخ التنفيذ: 2026-11-08. الفرع `feat/sunset-rush-visual-performance` مبني على `c4bd336` من `feat/coastal-arcade-racing`. عند الاستئناف كان الفرع نظيفًا ولم تكن تعديلات 3.0 السابقة محفوظة. اقتصر التنفيذ على المرحلة الأولى بناءً على طلب المالك الأخير. لم يتغير PR #1 أو main، ولم يحدث نشر.

## التغيير المنفذ

- بقيت الفيزياء وقرارات AI واللفّات والنتائج عند **60 Hz**، بنفس معادلات التسارع والفرملة والانجراف والنيترو. أُخرج تحديث مجسمات السيارات والكاميرا من خطوة المحاكاة.
- `src/presentation.js` يحفظ previous/current لكل سيارة من السيارات الخمس. يُستوفى الموضع والارتفاع والمقود وميل الهيكل والعجلات بين الحالتين، مع أقصر مسار زاوي للاتجاه. نتيجة العرض لا تعود إلى Cannon أو `RaceProgress`.
- `FixedClock.alpha` هو الجزء المتبقي من خطوة المحاكاة. يعمل العرض في كل إطار حتى عندما لا يحين موعد خطوة فيزياء جديدة. الاستيفاء يضيف تأخير عرض مقداره خطوة محاكاة واحدة كحد أقصى (نحو 16.7 ms)، ويتجنب تخمين موضع مستقبلي قد يخترق اصطدامًا.
- تتبع الكاميرا موضع السيارة المستوفى مباشرة، وتنعّم اتجاه المطاردة والمسافة والارتفاع وFOV باستخدام استجابة أسية تعتمد على الزمن. يمزج اتجاه المطاردة جزءًا من اتجاه الحركة أثناء الانجراف، وتحافظ زوايا المطاردة الثلاث على انتقال تدريجي.
- اهتزاز الكاميرا إشارة جيبية محدودة تُضاف بعد حساب موضعها ولا تتراكم فيه. الخيارات: **Off / Reduced / Full**، محفوظة منفصلة عن إعدادات التقدم. الافتراضي Reduced، أو Off عند `prefers-reduced-motion`.
- تُصفّر حوادث الانقطاع تاريخ الاستيفاء والساعة: إعادة السباق واستعادة السيارة والإيقاف/الاستئناف. يُصفّر توجيه السيارة وميلها والنيترو المرئي عند الاستعادة. لا يُمرَّر زمن قديم إذا استأنف المستخدم بيد التحكم أثناء قراءة مدخلات الإطار نفسه.
- أبقينا حد تعويض التوقف الطويل عند 12 خطوة (200 ms)، مع تسجيل الزمن المستبعد. لا تُحسب مدة إخفاء النافذة كلفّات أو تقدم سباق. فقدان سياق WebGL يوقف السباق ويحتاج استئنافًا صريحًا.
- لا تُنشأ مواد أو geometries أو textures داخل وحدة العرض الجديدة؛ تُعاد الاستفادة من كائنات الحالات. المرآب والسيارات الثماني والمضامير الأحد عشر والتقدم السابق محفوظة.

## قياس السلاسة قبل/بعد

القياس يحقن فواصل عرض 30/60/120/144Hz في دورة اللعبة الفعلية. في كل معدل، تُرسل المدخلات إلى المحاكاة عند 60Hz. بعد تسخين الحالات، تُقرأ مواضع اللاعب والمنافسين خلال ثانية من الحركة. **هذه ليست نتائج GPU FPS**؛ إنها قياس تكرار موضع المجسم بين خطوات المحاكاة.

| معدل العرض المحقون | إطارات موضع اللاعب المكرر قبل | بعد | أكبر انتقال بين عينتين قبل → بعد، بوحدات العالم |
| --- | ---: | ---: | ---: |
| 30 Hz | 0 | 0 | 1.6394 → 1.6318 |
| 60 Hz | 0 | 0 | 0.8233 → 0.8233 |
| 120 Hz | 60 | 0 | 0.8233 → 0.4117 |
| 144 Hz | 84 | 0 | 0.8233 → 0.3431 |

انخفض تكرار الموضع بالأعداد نفسها للمنافسين الأربعة. يستفيد العرض العالي من حالات وسطية فعلية، بينما تبقى وتيرة الفيزياء ثابتة. بيانات المقارنة والبيئة والكاميرا موجودة في [النتائج الخام](phase1-results.json).

## اختبارات المرحلة

- **15/15 اختبار Node**: اختبارات المشروع السبعة مع إضافة 120Hz، ثم ثمانية اختبارات للحالات المستوفاة، أقصر اتجاه زاوي، حدود الساعة، الاستعادة، ثبات تلامس Cannon عند المعدلات الأربعة، الكاميرا والاهتزاز.
- **10 فحوص Playwright للمرحلة**: سباق كامل في كل معدل، تطابقه مع 2.0، حركة السيارات الخمس بين الخطوات، عدم تغيير الحالة عند استدعاء العرض وحده، الإيقاف والاستعادة وإعادة السباق والتوقف الطويل وتغيير الكاميرا وحفظ خيار الاهتزاز وتقليل الحركة.
- **6 فحوص توقيت إضافية**: إيقاف/استئناف واستعادة عبر Gamepad داخل قراءة المدخلات، أول خطوة بعد الاستئناف، تبديل الكاميرا وفصل يد التحكم، وإشعارات فقدان/استعادة WebGL. فحص WebGL يستخدم أحداثًا اصطناعية، وليس فقدان GPU حقيقيًا. [نتائج التوقيت](timing-results.json).
- السباق المقارن عند كل معدل وعند النسخة السابقة: **60.783333 ثانية محاكاة، المركز الأول**، واللفات **21.083333 / 19.850000 / 19.850000** ثانية. تطابقت أيضًا الحالة النهائية ومواضع ومسافات وأوقات إنهاء المتنافسين الخمسة بعد 90 ثانية محاكاة. السائق الاختباري يرسل دواسات وتوجيهًا فقط.
- تلامس Cannon مختبَر مستقلًا مع منافس ثابت عند المعدلات الأربعة؛ لا نقدّم السباق النظيف دليلًا على حدوث اصطدام فيه.
- **18/18 فحص Playwright أصلي** ناجح دون أخطاء JavaScript: قيادة وفرامل وانجراف ونيترو، سباق كامل، منافسون وترتيب ثابت، إعادة السباق وثلاث سيارات، لمس متعدد وإلغاء اللمس، محاكاة هاتف 390×844 و844×390، المسار الكلاسيكي وبناء مسار النفق. [نتائج الرجوع](regression-results.json).
- نتيجة السائق الأصلي بقيت **60.933333 ثانية** كما في 2.0. اختلافها عن اختبار المقارنة الجديد سببه توقيت بدء مدخلات السائق الاختباري؛ كل اختبار طابق نسخته المرجعية.
- خمس إعادات سباق: موارد الرسم ثابتة عند **125 geometries / 5 textures** في هذه العينة. لا يكفي هذا لنفي جميع تسربات JavaScript heap.
- **اختبار الإنتاج ناجح**: `/sunset-rush/` يعمل دون اتصال بعد أول تحميل، والقيادة والإيقاف يعملان بلوحة المفاتيح؛ صفر طلبات خارجية وصفر أخطاء وغياب أدوات الاختبار الإنتاجية. Cache ID: `sunset-rush-6545db704598`. [النتيجة](production-results.json).
- البناء ناجح؛ يستمر تحذير حجم حزمة Three.js القديمة (508.43 KB قبل الضغط). لا توجد أدوات `__sunset` في JavaScript الإنتاج.

## قياس الرسم البرمجي الحالي

أعاد اختبار المشروع أخذ 30 عينة بعد الانتظار 32 إطارًا لكل جودة عند 1280×800، مع إيقاف تقدم المحاكاة وتحريك الماء. جميع المستويات سجّلت 167 طلب رسم و55,188 مثلثًا في لقطة القياس.

| الجودة الحالية | وسيط زمن الإطار | P95 |
| --- | ---: | ---: |
| عالية | 816.6 ms | 1599.9 ms |
| متوسطة | 800.0 ms | 1549.9 ms |
| منخفضة | 483.4 ms | 1066.6 ms |

الرسم البرمجي ما زال بطيئًا. هذه العينة ليست قياس Before/After مضبوطًا لسرعة GPU، ولا تثبت زيادة FPS من الكاميرا أو الاستيفاء. مقارنة المرحلة المضبوطة هي انتظام المواضع أعلاه؛ تحليل زمن الرسم وتحسينه مؤجلان للمرحلة الثانية. لم تُضف مؤثرات GPU أو أصول جديدة في هذه المرحلة.

## التجربة وإعادة الاختبار

```bash
git switch feat/sunset-rush-visual-performance
npm ci
npm run dev -- --port 5173
```

افتح `http://localhost:5173` ثم Play now. التحكم: WASD أو الأسهم، Space للانجراف، Shift للنيترو، C لتبديل الكاميرا، R لاستعادة السيارة، Esc للإيقاف. خيار Camera shake في الإعدادات. التحكم باللمس ويد التحكم السابقان متاحان.

```bash
npm test
npm run build
npm run test:phase1
npm run test:browser
npm run preview -- --port 4173 --base /sunset-rush/
# في طرفية أخرى:
npm run test:production
```

تستخدم اختبارات المتصفح Chromium في `/usr/bin/chromium`؛ يمكن تغييره عبر `CHROMIUM_PATH`. لمقارنة 2.0 مجددًا، شغّل worktree منفصلًا عند `c4bd336` على المنفذ 5190، ثم `BASELINE_URL=http://localhost:5190 npm run test:phase1`. أدوات المقارنة تُحقن في استجابة المتصفح فقط ولا تعدّل worktree المرجعي أو PR #1.
