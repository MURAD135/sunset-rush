# Sunset Rush 3.0 — تجربة نسخة المراجعة

هذه حزمة ويب/PWA للمراجعة، وليست IPA أو APK. لا تحتاج backend أو مفاتيح API أو CDN. تستهدف Safari على iOS/iPadOS وChrome على Android مع WebGL؛ اختبار الأجهزة الفعلية ما زال مطلوبًا، ولا يوجد ضمان FPS لها.

## الحصول على النسخة وتشغيلها

1. افتح [Draft PR #2](https://github.com/MURAD135/sunset-rush/pull/2)، ثم آخر GitHub Actions ناجح لنفس commit. من Artifacts نزّل `sunset-rush-3-review-…`؛ قد يلزم تسجيل الدخول إلى GitHub. مدة الاحتفاظ 14 يومًا.
2. فك ملف artifact الخارجي، ثم ملف `sunset-rush-3-review-….zip` داخله. `BUILD_INFO.json` يحدد commit ومعرّف cache وبصمات ملفات التشغيل. `SHA256SUMS` وملف `.zip.sha256` يتيحان التحقق من النقل.
3. على الكمبيوتر، داخل المجلد المستخرج: `python3 -m http.server 8080 --bind 127.0.0.1`، ثم افتح `http://localhost:8080/`. لا تفتح index.html عبر `file://`.
4. لتجربة الهاتف، يلزم رابط HTTPS أو خادم محلي موثوق الشهادة يمكن للهاتف الوصول إليه. أي نشر على الإنترنت ينتظر موافقة المالك. فتح localhost على الهاتف يشير إلى الهاتف نفسه، لا الكمبيوتر.

بديل من المصدر، باستخدام Node.js 24 وPython 3 للتغليف:

```bash
git clone --branch feat/sunset-rush-visual-performance --single-branch https://github.com/MURAD135/sunset-rush.git
cd sunset-rush
npm ci
npm run build
python3 scripts/package-review.py
npm run preview -- --port 4173 --base /sunset-rush/
```

## iOS Safari وAndroid Chrome

- افتح الرابط في المتصفح نفسه، لا متصفحًا مضمّنًا داخل تطبيق رسائل. اضغط Play لتفعيل الصوت وفق قيود المتصفح. جرّب أفقيًا وعموديًا.
- ابدأ بجودة Auto؛ جرّب Low وتقليل المؤثرات على الهواتف المتوسطة. مؤشرات FPS/P95/P99 في الإعدادات مفيدة للمقارنة، وليست ضمان أداء.
- اللمس: تسريع/فرامل/يمين/يسار/انجراف/نيترو، مع ضغط عدة أزرار معًا. الكمبيوتر: WASD/الأسهم، Space، Shift، R، Esc. إعدادات يد التحكم محفوظة في اللعبة.
- بعد اكتمال أول تحميل عبر HTTPS، يمكن إضافة اللعبة إلى الشاشة الرئيسية من قائمة المشاركة في Safari أو قائمة التثبيت في Chrome حيث يتيحها النظام. بيانات التقدم تحفظ لهذا المتصفح وهذا origin؛ نطاق تجريبي مختلف لا ينقل التقدم تلقائيًا.
- جرّب قطع الاتصال ثم إعادة الفتح بعد تحميل الأصول. النظام قد يحذف cache أو بيانات الموقع تحت ضغط التخزين؛ لا تعد هذه نسخة احتياطية للتقدم.
- عند تغيير نسخة المعاينة، أغلق تبويبات اللعبة القديمة كي يتفعّل service worker الجديد. لا تستخدم مسح بيانات الموقع كحل افتراضي لأنه قد يحذف التقدم.

## حدود التوافق التي يجب فحصها

اختُبرت نسخة الإنتاج في Chromium مع SwiftShader دون اتصال، وبالمسار الفرعي، ودون طلبات خارجية أو أدوات اختبار مكشوفة. اختُبر اللمس المحاكى في 390×844 و844×390. **لم تُختبر على iPhone/iPad/Android فعلي، ولم يُشغّل WebKit المحلي لغياب مكتبات النظام.** يلزم فحص الصوت بعد تبديل التطبيقات، دوران الشاشة، اللمس المتعدد، الحرارة، جودة Auto، فقدان WebGL وإعادة الفتح.

## خيارات HTTPS — لم يُنفذ أي نشر

| الخيار | المزايا | ما يلزم قبل التنفيذ |
| --- | --- | --- |
| Cloudflare Pages، مشروع مراجعة مستقل ورفع مباشر | يستضيف الملفات الثابتة مع HTTPS؛ يفصل المراجعة عن الموقع الحي | اختيار مشروع/نطاق جديد وسياسة وصول؛ إعداد Access إن أُريدت مراجعة مقيدة |
| Netlify، موقع مراجعة مستقل برفع يدوي | رفع محتويات الحزمة ومشاركة رابط HTTPS دون دمج | الموافقة على إنشاء الموقع، التحقق من إعدادات الخصوصية وخطة الحماية المطلوبة |
| Vercel Preview في مشروع مستقل | روابط معاينة وإمكانية حماية بحسب إعدادات الحساب | نشر يدوي أولًا؛ لا ربط Git تلقائي يسبب نشرًا عند كل push قبل الموافقة |
| HTTPS tunnel إلى خادم محلي | تجربة قصيرة على الهاتف دون استضافة دائمة | موافقة على تعريض منفذ الاختبار، تقييد الوصول وإغلاق النفق بعد الجلسة |

الاقتراح: مشروع Cloudflare Pages مستقل للمراجعة، لا نطاق اللعبة الحي، مع توضيح هل الرابط عام أو مقيد قبل النشر. GitHub Actions artifact **ملف تنزيل فقط**، وDraft PR **مراجعة كود فقط**؛ لا يمثلان نشرًا للعبة. لا نفعّل GitHub Pages في المستودع الحالي أو نغيّر إعدادات موقعه الحي دون موافقة.

## جلسة مراجعة عملية

اختر السيارة والمضمار الساحلي؛ أكمل ثلاث لفات مع أربعة منافسين، جرّب الانجراف والنيترو والتوقف والاستعادة، ثم أعد السباق وبدّل الجودة. سجّل الجهاز/نظام التشغيل/المتصفح والاتجاه والجودة، ومتوسط/P95/P99 بعد دقيقة تسخين، ثم بعد خمس دقائق للتحقق من الحرارة. أرسل الملاحظات عن التحكم والمشهد والصوت وأي خطأ، دون مشاركة بيانات شخصية.
